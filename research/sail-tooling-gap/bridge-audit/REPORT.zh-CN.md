# NEON / RVV reduction：本轮实验判断

**结论：类型差异可以接入，但正确的映射需要语义条件。Shared spec 不是必要条件，也没有替我们消除这些条件。现有工具尚未在本项目形成任意长度 kernel 的可检查等价性工作链。**

本轮最有价值的结果是：使用双方真实 ISA trace，已经能做一个带明确前提的算术小块比较，并能得到遗漏前提时的反例；NEON 侧还已把三条算术指令的已证结果函数转换成完整的局部求和规格。双方接口的精简对照见 [规格差异与映射](SPEC-COMPARISON.zh-CN.md)。剩下的问题从“泛泛的 type gap”具体化为：16 位累加范围、不同分块进度之间的状态关系、动态 vl 的 inactive lanes、内存可读性及可组合证明。

## 1. 我实际做了什么

起点是现有 `sail-binary-reduction/artifacts/neon.elf` 和 `rvv.elf`。重新核对机器码与 ELF 可执行段，盘点出 NEON 42 条、RVV 19 条静态指令，详见 [覆盖表](COVERAGE.zh-CN.md)。没有假设任一完整 kernel 已经接入。

| 层次 | 新完成结果 | 尚未完成 |
|---|---|---|
| Isla 提取 | NEON `uadalp` 两种、`addv`、加载、`mul`；RVV 扩宽、加法、符号地址加载、动态 vl 加法和扩宽 | 其余 kernel 指令没有本轮逐条完成接入；动态 vl 加载尚未尝试 |
| Coq 导入 | 13 个 trace 定义通过 `coqc`（含不同配置的探针） | 导入本身不证明行为 |
| 行为定理 | NEON `addv`、两种 `uadalp`、对齐加载的可组合契约；RVV 扩宽的第一 lane 性质也已完成 | RVV 扩宽的全部 lane/资源保持、加法与加载契约；双方实际控制流的组合 |
| 数学映射 | 两 lane 的 shared-spec 与 direct 证明、溢出反例、2048 字节块上界，以及真实 `bv 8/16/32` 类型间的扩宽引理，均经 Coq 检查 | 数值上界尚未由机器码循环不变量建立 |
| 双侧比较 | 实际算术 trace 的 16 字节组合，带范围条件的直接比较为 UNSAT | 不是整个控制流；不是任意 n；SMT harness 尚未认证 |

已有 RVV `vsetvl` 和 `vredsum` 定理保持原范围：前者量化 remaining，但固定架构配置；后者是 vl=64、任意输入 lane 数据的单条指令证明。两者均不等于 VLA kernel 已证。

### 延长等待的结果：RVV 扩宽定理完成

[RvvProof.v](RvvProof.v) 的**原版脚本**在 5564.047 秒（约 92.7 分钟）后 `coqc` 成功退出，`Qed` 完成，`Print Assumptions` 返回 `Closed under the global context`。[结果](results/attempt-RvvProof.json)和[日志](logs/attempt-RvvProof.log)可核对；没有使用实验插件或关闭内核检查。tactic 主阶段约 92.6 秒，`Qed` 约 5466.2 秒。此前十分钟未完成是时间预算不足，不是证明失败。

该定理仅证明：在 VLEN=256、vl=16、e32/m8/tu、目的寄存器组预置零等前提下，`vzext.vf4 v16,v2` 后 `vr16` 的低 32 位等于输入 `vr2` 低 8 位的无符号零扩展；输入数据是任意的。它没有证明整个目的寄存器组的结果或 inactive lanes，也没有保留完整后续状态，不能当成完整扩宽契约或 VLA kernel 定理。

另一个只做采样的诊断在 `Qed` 阶段多次采到 Coq 内核的 `Typeops.type_of_apply` / `Conversion.eqappr` / `CClosure` 调用。它支持“表达式转换比较是本次瓶颈”的判断，但不证明只有这一处原因，更不表示整个任务原则上不可行。诊断变体与已完成原版分开记录。

### 继续实验：加载阻塞已经解决

旧 RVV IR 中 `plat_ram_base`、`plat_ram_size`、`sys_pmp_count` 等是读取平台寄存器的普通 Sail 函数；只填写配置的 `const_primops` 对它们不起作用。`--no-model-reg-init` 下 RAM/PMP 寄存器未初始化，导致内存/异常路径大量分叉。补齐这些**平台寄存器的默认值**后，未修改 ISA IR，固定地址加载 6.833 秒完成；符号地址加载 10.656 秒完成。不能继续把这个旧超时当成 RVV 加载不支持或研究 gap 的证据。

修正后的 profile：Machine 模式、PMP count=0、RAM 为 `[0x80000000,0x84000000)`，`vl=16`，输入地址范围 `[0x80000000,0x83fffff0]`。这些条件保留在生成的 trace/前置条件中。对应 NEON 加载也提取了同范围、16 字节对齐的正常路径版本。NEON 执行两个 8 字节读并将输入指针推进 16 字节；RVV 执行 16 个字节读，指针由后续标量指令推进。因此应该在适当的小块边界比较，不能要求单条 load 后两边原始状态完全相同。[NeonLoadProof.v](NeonLoadProof.v) 已证明 NEON 的正常加载契约：对任意两个 64 位内存值，q2 等于它们按小端顺序拼接的 128 位值，R1 增加 16，内存、其他向量寄存器和输入系统寄存器保持。RVV 加载仍只有导入，尚无对应契约。

另一次不加对齐假设、并清除 SCTLR_EL2.A 的 NEON 探针仍提取出异常路径。当前 EL2/内存配置下，不能只删除对齐前提就沿用正常加载规格；`neon_load_unaligned` 是导入成功的诊断，未证明成功加载行为。

### 继续实验：NEON 的类型映射已连接到指令结果

[NeonPairProof.v](NeonPairProof.v) 从真实 `uadalp v1.8h,v2.16b` trace 证明完整的 128 位结果：八次无符号 byte-pair→halfword 累加，按 16 位取模，并保留其余向量寄存器及输入系统寄存器。另一宽度的 [NeonWordProof.v](NeonWordProof.v) 同样证明四次 halfword-pair→word 模加。`neon_uadalp8_result` 使用 mask/shift 表达完整寄存器更新，便于直接核对提取结果。

[NeonLaneBridge.v](NeonLaneBridge.v) 再证明它的第一 lane 恰好为 `h0 + zext16(b0) + zext16(b1)`（16 位模加）；在总和小于 65536 时，零扩到 32 位等于三项的 32 位相加。这条映射已经连接到实际指令的已证结果，不再仅是孤立的 Z 算术例子。后续的 [LanePacking.v](LanePacking.v) 已将该解释扩展到全部八个 lane 及整组求和；[WordPacking.v](WordPacking.v) 对四个 u32 输出给出同类结果。[NeonBlockSpec.v](NeonBlockSpec.v) 因而证明两种 `uadalp` 和 `addv` 的已证结果函数组合满足 `Σwords+Σhalves+Σbytes mod 2^32`。这里组合的是指令结果函数，不是二进制中间的完整控制流；循环不变量仍未建立。

### 继续实验：不固定单一 vl 的导入

`rvv_add_allvl` 保持 VLEN=256、e32/m8/tu，但输入 `vl` 为符号值，约束 `0≤vl≤64`，提取 92.225 秒、Coq 导入 73.519 秒。结果约 61.1 MB Isla / 1.98 MB Coq，有 64 个分支节点，覆盖当前配置下 65 个 vl 值。同配置的 `rvv_widen_allvl` 也在 91.524 秒内提取、73.118 秒内导入。两者消除了这些指令只能导入固定 vl=16 的局限，但还不是动态 vl 行为定理。

在固定硬件 VLEN 上，对所有合法 vl 建立指令契约，再用归纳处理任意输入长度 n，本身可以得到任意 n 的证明；指令的有限 vl 域不等于把整个 kernel 的 n 固定住。不过这份产物目前是分支展开，既没有循环归纳，也不是对所有 VLEN 的统一参数化证明。

常规重放共 27 项检查通过（包括故意写错运算的预期失败），十一份 NEON/数学证明另经 `coqchk` 独立复核（95.183 秒）。RVV 原版扩宽定理由单独的长时间 `coqc` 运行完成，不计入这 27 项，也未另跑一次可能同样耗时的独立 `coqchk`。合计十二份本轮证明文件已通过 Coq；验证层次分别保留在结果中。

## 2. Type 到底差在哪里

| 差异 | 实际观察 | 需要做的工作 |
|---|---|---|
| 寄存器容器 | ARM `_V` 是含 32 个 `bv 128` 的 `RegVal_Vector`；RVV 是 `vr0`…`vr31`，每个在旧模型中为 `bv 65536` | 编写读写/解码规则。NEON `addv` 已证明这种容器可以进入 Islaris 自动化；不是必须统一底层 Coq 类型 |
| 存储宽度 vs 架构宽度 | 本轮 RVV 的架构 VLEN=256，而模型寄存器存储宽度是 65536；m8 组跨 8 个寄存器 | 只解释配置下有效的位段；不能把 65536 位都当成实际硬件 lane，也不能未经证明改成 256 位模型 |
| lane 宽度 | NEON：u8 成对加到 u16，再成对扩到 u32；RVV：u8 直接扩到 u32 后累加 | 明确 unsigned 解码、零扩展、模运算，以及中间 u16 不溢出的前提 |
| 分块结构 | NEON 每次 16 字节，并在最多 2048 字节后提升中间累加；RVV 每次消费由 vl 决定的字节数 | 两侧 lane 无需一一对应。需要把累加寄存器解释成“已消费前缀的总和”，并建立跨不同执行进度的关系 |
| 动态长度状态 | RVV 的 `vl`、`vtype`、`vstart`、m8 和 tu 都影响行为 | 循环不变量必须追踪有效/未激活 lane，特别是末次 vl 变小时旧累加值的保留 |
| 内存与异常 | NEON 向量加载正常路径拆为两次 8 字节读，trace 也含异常路径；RVV 在明确平台配置下已提取 16 个字节读的正常路径 | 对齐、地址范围、配置和异常条件必须进入前置条件/契约；不能只比较寄存器算术 |

第一、二项主要是表示和自动化工程。第三至第六项是必须证明的语义义务，不能靠 `cast` 或转换数据结构解决。

特别注意：本轮 ARM 配置是 Islaris 原有的 EL2 环境，RVV 是 Machine 模式。它们只是受约束的实验执行环境，还不是所有用户态程序合法输入/异常情形的完整建模。

## 3. 双方的小块规格与映射

先从加载后的寄存器开始，输入为任意 16 个字节 `b[0..15]`、8 个任意 u16 中间累加值 `h[0..7]`、一个任意 u32 累加值 `acc`。

NEON 使用 ELF 中实际的三条算术指令（从不同控制流位置抽取，本实验按下面次序组合，不能当成实际连续基本块）：

```text
uadalp v1.8h, v2.16b
uadalp v0.4s, v1.8h
addv   s0, v0.4s
```

初始 `v1` 解码成 h，`v2` 解码成 b，`v0` 的第一 lane 为 acc、其余为 0。这是在抽出的算术片段中指定初始关系，不是声明真实 kernel 每次都具有这个特殊 v0 布局。

RVV 使用实际的 `vzext.vf4 v16,v2` 和 `vadd.vv v8,v8,v16`，在 vl=16、VLEN=256、e32、m8、tu 下执行。初始把 `h[i]` 放入第 `2*i` 个 u32 累加 lane、配对的奇数 lane 为 0，acc 加到 lane 0；其他累加 lane 为 0。最终观察值是累加组 64 个有效 u32 lane 的模加和。

**这里 RVV 的最终求和是观察函数。没有在本 harness 中执行 `vsetvl`/`vredsum`，也没有证明它们与这个片段的状态交接。** 之前的单条 `vredsum` 定理说明了这类观察函数的 ISA 实现，但尚未完成组合。

候选 shared spec 是：

```text
F(acc,h,b) = (acc + Σ h[i] + Σ b[j]) mod 2^32
```

所需范围条件：

```text
对每个 i：h[i] + b[2*i] + b[2*i+1] < 2^16
```

直接关系路线也需要相同条件。若漏掉它，初始 `h[0]=65535`、`b[0]=1`，其余及 acc 为 0，NEON 输出 0，而 RVV 观察值为 65536。该反例同时有 SMT 检查和 [Coq 算术证明](Mapping.v)。它否定的是**无条件的中间状态映射**，不是当前原始 kernel 的正确性。

实际 NEON 代码每个中间块最多进行 128 次 pair 累加，每次至多 `255+255=510`，因此上界是 `128*510=65280<65536`。[Coq 已检查这个数值推理](Mapping.v)，但循环确实从零开始、恰当清零、最多运行 128 次等事实，还需要连到真实机器码控制流。

## 4. 实验结果如何解读

来自 [block-comparison.json](results/block-comparison.json)。每项首先检查前置约束可满足，避免把不可执行状态下的 UNSAT 当成成功。

| 检查 | 求解结果 | 本次时间 |
|---|---|---|
| 加范围条件，直接比较双方观察值 | `sat / unsat`，通过 | 26.427 秒 |
| NEON 与 flat-sum shared spec 比较 | `sat / unknown`，未完成 | 60.446 秒 |
| RVV 与同一个 shared spec 比较 | `sat / unsat`，通过 | 0.476 秒 |
| 去掉范围条件，寻找不等价输入 | `sat / sat`，找到反例 | 0.694 秒 |
| 初始 h 全零，直接比较 | `sat / unsat`，通过 | 9.246 秒 |
| 指定 65535+1 的反例 | `sat / sat`，通过反例检查 | 0.467 秒 |

因此记录为 **5/6 得到预期结果，1/6 unknown**，不是“全部证明成功”。就逻辑而言，已通过的直接关系与 RVV→F 可以推出 NEON→F；表中的 unknown 是独立求解那条扁平公式失败，不是发现 shared spec 错误。后续新增的 `NeonBlockSpec.v` 已用 Coq 证明对应的 NEON 局部求和规格；表中保留的 `unknown` 仍准确记录那次独立 SMT 查询的结果。

两种公式组织的耗时不同，不足以推出 direct 方法一般优于 shared spec。这只是一个算术形状、一个求解器预算、当前主机上的诊断结果。初版没有把 fresh read 变量立即替换为寄存器值时，直接关系也返回 unknown；改善表示后才完成。这是明确的工程收益，尚不是新的理论结果。

Coq 的 [Mapping.v](Mapping.v)分别完成了两种路线的两-lane 版本。[TypeBridge.v](TypeBridge.v)进一步给出基于实际寄存器容器的观察函数，以及对 `bv 16` 累加器和两个 `bv 8` 输入成立的、带不溢出前提的 16→32 位扩宽引理。观察函数尚未由完整 ISA 执行证明实现；类型引理本身已经内核检查。两者都需要同一条范围假设。这里 shared spec 的价值在于把 lane 重排、不同分块解释成同一个总和，便于复用；它既非逻辑必需，也不是自动 bridge。

## 5. 离真正任意长度证明还缺什么

1. **补齐实际指令与内存契约。** RVV 加载提取已解决、NEON 对齐加载契约已证明；接下来补 RVV 加载契约，并把两种内存分块解释成同一输入 byte sequence。逐条覆盖表中的其余算术、分支、初始化、标量尾部与返回尚须处理。
2. **给现有算术 trace 建立可组合的 lane 摘要。** 要证明整个活动 lane 范围及 tu 保留关系，返回后续指令需要的寄存器资源，而不仅是第一 lane 或最终一个值。摘要必须从 ISA trace 导出并检查，不能让 agent 手写后直接信任。
3. **建立前缀总和关系和进度关系。** NEON 与 RVV 不同步走同样多次循环；各自维护“已消费输入前缀 + 未消费后缀”的不变量，在适当切点比较总和。要证明 RVV 每轮消费正数、剩余长度减少，而不是给执行轮数固定上界做展开。
4. **覆盖动态 vl 与尾部。** 不能把 `vl=16` 或 `vl=64` 写进最终整个循环的假设。还要区分“任意输入 n，在给定硬件 VLEN 上成立”和“对所有支持的 VLEN 均成立”。这轮两者都没有实现。旧 Sail 快照的 `vsetvl` 还可能在 64<n<128 时选择平衡分块，例如 n=65 选 33，不可擅自替成 `min(n,64)`。
5. **定义完整的外部可观察结果与合法输入域。** 输出是旧 u32 输出值加字节和模 2^32，外加写入位置/范围、返回和终止性质。数据区通过地址映射对应；PC、寄存器文件、代码区无需逐位相同。NEON 的不足 16 字节尾部仍进行完整向量加载，需证明 padding 可读或修改实现，再处理掩码。相同数学输出不自动保证异常、内存访问和终止一致。

原有 Iris/Islaris WP 定理也不能不经审查就当成“两边都必定终止”的总正确性定理；最终等价性定义须明确终止、安全和输出观测，并补充所需证明。

## 6. 研究判断与下一步选择

**值得继续研究，但贡献应聚焦“从真实 ISA trace 到可检查的、支持变长循环的关系摘要及组合”，不宜表述成“让 LLM 写 shared spec 就解决跨 ISA”。** 本轮尚不能支持“已有工具加少量 glue 已能完成任意长度验证”的判断，也不足以证明现有文献中没有其他工作；这是项目可行性实验证据，不是穷尽文献后的新颖性结论。

建议的路线是：底层保持各自模型类型；先用局部关系解释 lanes 和累加状态；用一个很薄的共同 byte-sequence/模加总和作为外部观测。让 agent 提议映射、范围不变量和 Coq 脚本，最终由证明检查器验收。这样可以同时使用 shared spec 的可读性和 direct relation 对局部优化的适应性。

下一个真正有决定性的验收点是：**双方真实 load→widen/accumulate 小块的可组合 Coq 定理，RVV 的 vl 不固定为单一值，并证明 inactive lane 保留；随后连接到任意 n 的循环。** 若这些定理能跨多个 reduction/优化复用，才逐渐构成可评估的研究方法。单独支持一个容器类型、固定 16 字节 SMT 通过或人工写出 F，都不足以支撑目前设想的贡献。

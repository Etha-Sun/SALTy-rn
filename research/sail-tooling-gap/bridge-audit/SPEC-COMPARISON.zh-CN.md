# 双方实际需要什么规格，以及怎么对应

**底层规格不同，外部观测可以相同。** 不需要先把 ARM 和 RVV 的寄存器类型统一，也不能只把类型转换好就宣布等价。这里区分已经检查的指令结果、已检查的数学映射、尚待证明的循环关系。

| 层面 | NEON 侧 | RVV 侧 | 对应条件与当前证据 |
|---|---|---|---|
| 输入内存 | `ldr q2,[x1],#16`：两个 64 位读，拼成 128 位；同时推进指针 | `vle8.v v2,(a1)`：当前探针读 16 个字节；指针由后续指令推进 | 要把两种读取解释成同一字节序列。NEON 对齐加载契约已检查；RVV 只有 trace 导入；跨两种内存资源布局的定理未完成 |
| 原始寄存器 | 一个含 32 个 `bv 128` 的向量寄存器文件 | 独立的 `vr0`…`vr31`，旧模型各用 `bv 65536` 存储 | 使用解码函数，无需原始类型相同。RVV 实验的实际 VLEN 是 256，不能把整个存储宽度解释成硬件向量长度 |
| 中间累加 | 每对 u8 加到一个 u16，按 2^16 取模 | u8 扩到 u32，再按 2^32 累加 | NEON 每 lane 的 `h+x+y<65536` 是必要条件；已有与真实 NEON 输出相连的 Coq 证明和溢出反例 |
| 整组数学结果 | 三条算术指令的已证结果函数可组合成 `sum(words)+sum(halves)+sum(bytes) mod 2^32` | 候选观察是 m8 累加组有效 u32 lanes 的模加总和 | NEON 结果函数到该规格的转换已经 Coq 检查；RVV 扩宽仅完成目的组为零时的第一 lane 性质，加法契约未完成，尚不能合成双侧 Coq 等价性定理 |
| 执行进度 | 每次处理 16 字节；中间累加定期提升到 u32 | 每次处理由 `vl` 选择的字节数 | 应在切点用“已消费前缀的总和”联系状态；不要求逐指令或逐轮对应。目前只是关系设计，未证明实际循环保持 |
| 尾部与范围 | 要证明 u16 累加次数上界；不足 16 字节的加载还涉及可读 padding 和掩码 | 要处理末轮较小 `vl`、tu 下旧 inactive lanes 的保持及最终归约 | 这些条件不能由 shared spec 省掉；仍需实际控制流与内存证明 |
| 合法输入与环境 | 已证加载限定给定 RAM 范围、16 字节对齐及 EL2 配置 | 当前加载探针限定 RAM 范围、Machine 模式、PMP count=0 | 尚未建立覆盖最终项目输入域的共同前置条件。删除对齐条件的 NEON 探针仍有异常路径，不能直接复用正常加载定理 |

## 已检查的转换是什么

`LanePacking.v` 证明八个 NEON u16 输出 lane 的精确公式，并在每个 lane 不溢出时，把它们的 32 位求和转换成原累加值之和加 16 个输入字节之和。`WordPacking.v` 证明四个 u32 输出 lane 的精确公式与求和规则。

`NeonBlockSpec.v` 使用这些规则，把 `uadalp` 两种宽度和 `addv` 的**已证结果函数**组合成下面的规格：

```text
F(words, halves, bytes)
  = (Σ four u32 words + Σ eight u16 halves + Σ sixteen u8 bytes) mod 2^32

前提：每个 i∈[0,8)，halves[i]+bytes[2i]+bytes[2i+1] < 65536
```

这些函数分别来自真实 ISA 指令的行为定理；该组合尚未包含真实二进制中间的分支、清零、计数和返回，也尚未与 RVV 的指令契约组合。它是一份有 ISA 依据的局部规格，不是完整 reduction kernel 的规格证明。

## Shared spec 与 direct relation 的选择

- **Shared spec：** 分别证明两边输出等于同一个模加总和。适合说明对外结果和复用不同实现。
- **Direct relation：** 直接证明两边解码后的观察值相等。适合局部变换和不对称的中间状态。

两者都必须处理不溢出、输入域、内存、副作用和循环进度；共同规格不会免费提供这些关系。当前最合理的设计是保留两侧原生指令契约，用已检查的 lane/内存映射衔接，并在外部观测层保留一个很薄的总和规格。

最终目标仍是**任意满足合法输入条件的长度 n**，通过循环归纳证明；固定 16 字节探针用于确定上述接口。固定 VLEN 上覆盖全部合法 vl，可以服务于任意 n 的证明，但本轮的动态 vl 产物尚停留在 trace 导入。

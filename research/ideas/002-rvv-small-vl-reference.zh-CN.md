# 用小 vl 参考执行简化 RVV 验证

记录与调研日期：2026-10-02。状态：候选方向；通用的小规模充分性不成立，受限程序类的推广定理值得探索。

**用户原话**：

> 第二个想法是，我们尝试去验证vl=1和vl=任意值时，程序是基本等价的，或者有些并行问题，只需要验证vl=2时和其他是完全等价的，这个可行吗？然后我们再验证vl=1和vl=2在output层面是等价的。老师说这实际上引入了一个更大的证明义务，但是我还是想探索一下这个靠不靠谱，rvv官方有没有对这个的回复

**当前解释**：暂按总输入长度保持任意、修改循环每轮请求的元素数为 1 或至多 2 来分析；最后不足 2 个元素时仍须正确处理。初始化和最终归约的长度设置需单独定义，不能一并机械改成 1 或 2。用户尚未明确这是否也包括缩小硬件 VLEN 的方案；`vl`、硬件 VLEN、当前配置容量 VLMAX 是不同参数。

**两个需要区分的命题**：

- 先证明一般 RVV 执行与小 vl 参考执行输出等价，再使用参考程序完成规格或跨 ISA 验证。这是可成立的证明分解方式，但第一条等价桥仍需证明。
- 只验证 vl=1 和 vl=2，便推断所有 vl 正确。这需要另一个小规模充分性定理，RVV 没有为任意程序提供这种保证。即使这两个版本对所有合法输入输出相同，也不足以推出较大 vl 的结果。

用 `Kπ` 表示按分块策略 π 执行完整输入的程序，`K1` 表示已明确定义的逐元素参考版本。第一种方案的核心目标为：对所有共同合法输入 x 和目标范围内的策略 π，`output(Kπ, x) = output(K1, x)`。若该范围已经覆盖两元素分块，则 `K1` 与 `K2` 的等价可由这个定理推出。如果不同程序类分别归约到 `K1` 和 `K2`，两个参考之间的连接仍有用。要完成 cross ISA 验证，还需把参考程序连接到 NEON 或共同规格。

**为什么老师的疑虑有依据**：如果原目标只验证一个固定硬件配置和固定 VL 策略，推广到所有分块策略会增加量化范围；把原循环强制成 vl=1 还可能引入原程序没有的执行方式。若原目标本来就要求所有合法策略都等价于同一个确定的源程序，则输出不依赖这些策略已经隐含在目标中，此时新增的是证明分解和辅助引理的成本，不能一概说逻辑目标更强。

可行性的关键是能否把这些辅助引理做成可复用的程序类定理。若每个 kernel 都重新证明一套任意 vl 等价性，成本可能与原验证相当或更高；是否划算尚无本项目对照实验。

**不能由 1 和 2 推广的一般反例**：考虑每轮局部下标为 j 的元素执行 `out[base+j] = in[base+j] + (j == 2)`。循环每轮最多处理 1 或 2 个元素时，对所有输入都是复制；每轮处理 3 个元素时，会修改每块的第三个值。这个思想实验可用 RVV 的元素下标、比较和算术操作表达，说明即使没有数据竞争，小规模行为也不能代表任意规模。它不是对项目某个 kernel 的实测反例。

**RVV 官方材料及查找边界**：

本次查阅 RVV 1.0 规范、官方 ISA 仓库相关段落，并搜索归档规范仓库的 reduction、vl=1、verification 相关 issue。没有找到“vl=1 或 vl=2 足以验证任意 RVV kernel”的规范保证或直接官方答复；这不是对全部历史讨论的穷尽性结论。找到的相关证据如下。

- [RVV 1.0 第 2、6.3、14.3 节](https://github.com/riscvarchive/riscv-v-spec/blob/v1.0/v-spec.adoc)：跨硬件可移植性带有约束；`vsetvl` 返回值受 AVL/VLMAX 规则限制；有序与无序浮点归约有不同要求。例如 VLMAX=8、AVL=8 时必须返回 8，强制返回 1 不属于该请求的合法实现选择。
- [官方 issue 124](https://github.com/riscvarchive/riscv-v-spec/issues/124)：2019-03-29，Andrew Waterman 提议明确有序归约先加入标量初值，以适用于自动向量化；2019-04-19，Krste Asanović [回复](https://github.com/riscvarchive/riscv-v-spec/issues/124#issuecomment-484915503)“TG agrees.”。这是特定运算顺序的设计依据，不是小 vl 截断验证定理。
- [官方 issue 386](https://github.com/riscvarchive/riscv-v-spec/issues/386)：讨论允许无序浮点归约使用更宽精度的归约树；John Hauser 提出具体规则，Andrew Waterman [支持该放宽](https://github.com/riscvarchive/riscv-v-spec/issues/386#issuecomment-592721962)。历史讨论需与最终规范一起阅读，不能把无序归约默认解释成固定的标量逐次求和。

**按程序类评估的候选方向**：

| 程序类 | 助手的可行性判断 | 核心证明义务 |
| --- | --- | --- |
| 各元素采用相同运算、内存无干扰的逐元素程序 | 最适合先探索逐元素参考 | 任意活动 lane 的语义、地址对应、mask/tail 不影响已定义输出、循环完整覆盖 |
| 当前 qu8-rsum 形式的模 2^32 整数累加 | 适合用总累加值连接不同分块 | 扩宽与模运算一致、非活动累加 lane 保留、最终归约覆盖有效累积 |
| 每块用前块标量结果作 seed 的有序浮点归约 | 可在保持全局加法顺序等条件下探索 | 精确 seed 传递、元素顺序和浮点环境；不能先计算各块局部和再任意合并 |
| 跨轮次 lane 浮点累加、无序浮点求和、跨 lane 重排等 | 需逐项判断，存在不等价情况 | 浮点舍入、全局与局部下标、跨块依赖、内存别名和有效 lane 的精确对应 |

“有些问题只涉及两个 lane”可以启发验证两个任意符号下标的局部无干扰性，但不能直接推出整个系统存在大小为 2 的充分界限。还需证明所有全局行为都能由这些局部关系组合，且没有依赖更大规模的行为。

**项目已有基础和本次复查**：

- [VL 建模笔记](../VL-MODELING.zh-CN.md) 已分析小 vl 参考和分块无关性的边界。本次重新编译运行其 [浮点反例](../vl_partition_witness.c)：输入 `[2^24, 0, -2^24, 1, 0, 0]`，四个 lane 累加、最终有序归约时，合法分块 `[4,2]` 得 1，`[3,3]` 得 0，逐元素分块得 1。使用 `cc -std=c11 -O0 -frounding-math ... -lm`，断言通过。这是主机 binary32 语义复现，不是 RVV 硬件执行，也不是原项目浮点 kernel 的具体反例。
- [Schedule.lean](../../src/verification_bw/lean/SALT/Kernel/Schedule.lean) 已包含抽象的任意完整分块等于 map/zipWith 的定理。当前阅读确认了源码；本次没有重跑 Lean，真实 ISA 到这些抽象的连接仍需证明。
- [RvvStepMath.v](../sail-tooling-gap/kernel-e2e/RvvStepMath.v) 的 `step_words_sum` 将一次动态长度累加连接到本轮字节之和。这是固定八个累加 lane 的抽象算术基础；真实加载仍有未完成义务，不能当作完整分块无关性已经证明。

**建议保留的研究问题**：能否针对受限的 RVV 程序类，证明并复用到小 vl 参考执行的归约定理，从而降低后续 kernel 的 cross ISA 验证成本？先用逐元素 kernel 验证 ISA 连接与分块推广，再扩展到整数 reduction；以直接任意 vl 验证为基线，计入定理库构建成本和每个新 kernel 的成本。vl=2 只在发现并证明明确的局部交互条件后再引入。

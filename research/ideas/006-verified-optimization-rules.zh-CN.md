# 从实际 kernel 优化提取可复用的已验证规则

日期：2026-10-30。状态：已做定向调研的候选方向；尚未实现规则系统、证明新规则或运行成本对照。

## 用户原话

> 我有一个想法，鉴于我们现在已经建立了c semantic 的语义用于做验证，在semantic model上积累了一些经验，你能否看看[https://arxiv.org/pdf/2505.18574](https://arxiv.org/pdf/2505.18574) 以及salty rn中的一些核优化的过程，你看看能否将这些优化提取成一些形式化的rule，并且思考，这样的rule有没有一些可验证的性质，同时也要调研一下对应的文章，我现在比较好奇这样的优化都是什么形式的，可以给他分分类，我也不清楚，这个组织形式是在c上更好表示还是ir 或者assembly，你需要调研一下，这个方向有没有什么可做的空间。这样，如何我们能抽象出一些已经验证的优化规则，那么这个就大大减轻了形式化的负担。

## 助手解释与本轮结论

目标是把已见优化转成带前提的参数化变换定理，使新 kernel 主要证明适用条件并组合旧定理。这里须区分指令语义库、优化规则库和规则应用策略；已有指令定义不自动证明优化，某个优化实例通过也不自动证明参数化规则。

建议先在现有 C intrinsic 前端之后，以保留循环、活动 lane、内存效果和数值模式的薄语义 IR 表达规则。C 保留为实际输入/输出；assembly 用来检查性能与按需补语义桥。不是立即重写前端或采用完整 LLVM 语义。

具体分类、四张候选规则、文献比较、反例与实验合同见[完整调研](../verified-optimization-rules-20261030/REPORT.zh-CN.md)。本轮直接阅读了 IGEMM/softmax 原版与候选 diff，也核对了另一个工作目录中固定的 Autocomp RVV 菜单；没有修改或介入该目录实验。

最接近的已有工作是 ATL（POPL 2022）、Exo 2（ASPLOS 2025）、Isaria（ASPLOS 2024）、Alive/Lean-MLIR；因此“规则证明一次再复用”本身不是新颖性。候选贡献是针对真实 C intrinsic kernel 的 VL/tail/packing/严格数值语义，自动恢复条件化变换，并以跨 kernel 实验证明摊销收益。

## 证据边界与下一步候选

- 当前 C→Lean 路线的任意长度结果是逻辑值等价；完整 C 内存、ISA 和编译器桥尚未覆盖。新规则不能继承不存在的端到端保证。
- IGEMM 展开/加载前移/LMUL 调整、softmax 固定 VL 主循环是候选规则来源，历史测试不是规则定理。
- 建议先比较同一组优化边的逐实例验证与规则实例化；首次证明库和前端成本也计入。按 kernel 家族留出，不能只在同一 kernel 的多个尺寸上报告复用。
- 首批：顺序展开、逐元素完整分块、受限 LMUL 调整、保留尾部策略的固定 VL 主循环；内存桥作为独立门槛。浮点重结合和异步流水化后置。
- 与 idea 001 的共同规格、idea 002 的分块无关性相连，但本想法的主问题是优化变换本身及其证明成本，而非仅组织顶层跨 ISA 结论。
